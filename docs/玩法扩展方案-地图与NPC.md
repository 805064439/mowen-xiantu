# 墨问仙途 · 玩法扩展方案：地图 与 NPC 操作

> 2026-10-12 · 基于 v3.12.5 代码摸底。候选项目见文末清单，由你勾选后逐项实现。

---

## 一、现状摸底

### 地图 / 地点：目前是「完全没有」的状态

| 事实 | 依据 |
|---|---|
| 状态里**没有** location 字段 | `sanitize_state()` 白名单无此键 |
| 地名只活在 AI 叙事文本里 | 青牛山 / 青牛镇 / 乌山镇 / 越岭 / 芦荡废坞 / 渡口……全是模型每轮现写 |
| 探索 = `tag:"explore"` + 风险三档（25~60 天等） | 纯文字驱动，与"去哪"无关 |
| 敌人按**境界区间**出没（`lo/hi`），不绑地点 | `ENEMY_DATA` |
| 坊市是固定价格纯代码端点，不绑地点 | `/api/shop` |

**⚠️ 一条血泪教训必须先摆出来**：v3.11 追索机制"找人找了 10 轮"的 bug，根源就是 **AI 每轮换地名**导致计数指纹失效。所以地图功能的高压线是——**地点必须白名单 + AI 申报制**（`npc_updates` / `thread_updates` 同款模式，代码侧 sanitize 钳死），绝不能让模型自由编地名。

### NPC：记录很完整，但**完全被动**

| 现状 | 依据 |
|---|---|
| 有完整记录：`state.npcs`（上限 6 人），含 name / title / bond（-100~100）/ met_turn / alias / fired | `apply_npc_updates()` |
| 道缘增减靠 AI 每轮申报 `npc_updates` | |
| 道缘阈值**自动**触发天机事件：赠宝 ≥70 / 传功 ≥70 / 寻仇 ≤-55 | `check_npc_events()` |
| 前端只有展示：主面板 3 个 chip + 抽屉道缘条 | `StatusPanel.vue` / `StatusDrawer.vue` |
| **玩家对 NPC 零主动操作**——点开都没有详情页 | |

**回答你的问题：NPC 是会记录的**（六人册，超出按价值淘汰最边缘者）。缺的是"玩家能对名册里的人做什么"。

## 二、两条设计约束（本项目高压线，任何方案都不能破）

1. **数值必须过蒙特卡洛仿真**（`tools/sim_lifespan.py`）。寿元经济是全身最敏感的神经——v3.2.4、v3.3.1 两次配平事故都出在"行动换天数"上。凡是"耗天数"的新动作都要重新标定。
2. **AI 自由输出一律走申报 + 白名单钳制**。地名、人名、线索，凡进状态的都不许模型直写。

---

## 三、地图方案（两个档位，可只做一个）

### M1 · 地图可视化（纯展示，不动数值）　**复杂度：低**

- 后端加地点白名单表（8~12 个固定地点，配类型：山门/城镇/坊市/险地/秘境）；
- `state.location` + AI 经 `location_update` 申报移动（白名单钳制，编地名直接丢）；
- 前端加「舆图」弹窗：水墨风静态地图（SVG，延续现有风格），当前位置高亮，地点悬停显示简介与"传闻"（从 threads/memory 里摘）；
- 页脚加一个「舆图」入口按钮（参考现有 坊市/对局日志 模式）。

改动面：server（地点表 + sanitize + 提示词注入"你当前在X"）+ 1 个前端组件 + 1 个按钮。
风险：低。**不碰天数、不碰掉率**，仿真不用重跑。
收益：世界第一次有了"形状"，玩家记得住自己走过哪。

### M2 · 地点特色与移动消耗（绑玩法）　**复杂度：中高**

M1 之上再叠加：

- 玩家在地图上点目标地点 → **移动消耗天数**（按距离档位），这一轮叙事就是"赶路"；
- 地点绑定玩法差异：探索的敌人池/掉率池按地点过滤（北荒泽出高 tier、青牛山只出小妖）；坊市按地点差异商品；灵脉之地闭关效率加成；
- 提示词把"当前地点 + 邻近地点"喂给 AI，叙事被约束在地理上一致。

改动面：数值层 + `sim_lifespan.py` 重新标定 + 提示词 + 前端可交互地图。
风险：**高**——移动天数直接冲击寿元经济，是历史事故高发区，必须仿真验证后才敢上。
建议：**M1 先落地跑一阵子，M2 单独评估**。也可以折中 M1.5：移动耗天数但地点不绑数值差异（配平压力小一半）。

## 四、NPC 方案（三个档位，自由组合）

### N1 · NPC 详情卡　**复杂度：低**

- 点主面板 chip / 抽屉卡片 → 弹详情：结识轮次、道缘条与称谓（生死之交/死敌等）、已触发过的事件（赠宝/传功/寻仇）、与 TA 相关的最近记忆（memory 里按名字+alias 搜）；
- **纯前端**，现有状态全够，一行后端都不用改。

改动面：1 个前端组件。
风险：无。
收益：名册从"装饰条"变成"人物档案"，也是 N2 的入口载体。

### N2 · NPC 主动操作（本次诉求的正解）　**复杂度：中**

照 `/api/shop` / `use_item` 的成熟先例，加**纯代码裁决**端点 `/api/npc`（或 action_type 扩展），详情卡里挂操作按钮。候选操作（可全做也可挑）：

| 操作 | 效果 | 消耗 / 防刷 |
|---|---|---|
| 拜访赠礼 | 送灵石或物品 → +道缘 | 道缘越高衰减越大（对数曲线）；同一人有冷却轮数 |
| 论道 | bond≥30 → 少量修为 | 受单轮修为 cap 约束，耗天数 |
| 切磋 | 复用斗法判定 `run_fight_trial`：胜 +bond / 负 -HP、-bond | 耗天数，有受伤风险 |
| 打听消息 | 推进在册线索（与追索机制联动，给指向性提示）或问出机缘传闻 | bond≥20 才肯说，耗天数 |

叙事走"代码给骨架 + AI 补皮肉"的轻量模式，数值全在代码手里。
改动面：server 一个端点（约 150~200 行）+ N1 详情卡挂按钮 + 测试。
风险：中——主要防"刷道缘"，靠衰减 + 冷却 + 耗天数三重阀门；仿真跑一轮确认无副作用。
收益：**NPC 从"会自己动"变成"能主动经营"**，修仙味一下就出来了。

### N3 · 关系深度（结拜 / 师徒 / 道侣）　**复杂度：高**

- bond≥90 可结契，给长期 buff：结拜（探索掉率+）、师徒（修炼效率+）、道侣（静养/道缘联动）；
- 涉及新的长期状态、结契仪式叙事、**结局与轮回时的交代**（道侣怎么办——这是叙事大坑）、提示词大改。

改动面：状态 + 结局系统 + 提示词 + 仿真，全线动。
风险：高。建议 N1+N2 上线后看玩家反馈再决定。

## 五、候选清单与推荐组合

| 编号 | 项目 | 复杂度 | 碰数值/仿真 | 依赖 |
|---|---|---|---|---|
| M1 | 地图可视化（白名单地点 + 水墨舆图） | 低 | 否 | — |
| M1.5 | 移动耗天数（不绑数值差异） | 中 | 轻 | M1 |
| M2 | 地点特色（敌人/掉率/坊市按地点分化） | 中高 | **是** | M1.5 |
| N1 | NPC 详情卡 | 低 | 否 | — |
| N2 | NPC 主动操作（赠礼/论道/切磋/打听） | 中 | 轻 | N1 |
| N3 | 关系深度（结拜/师徒/道侣） | 高 | **是** | N2 |

**我的推荐**：`N1 + N2 + M1` 一次做——两个都是低风险，互相还咬合（地图上标"故人所在"，NPC 详情里写"现居 X 地"，世界一下就活了）。M2 / N3 留给下一版。
